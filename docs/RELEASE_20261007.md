# Bill numbers, role access and recovery — October 7, 2026

## Release behavior

- Every newly saved cloud transaction receives `OLP-000001`, `OLP-000002`, etc., unique
  within the ledger across categories, roles and devices. The server counter is atomic;
  clients cannot choose bill numbers. Retries return the original bill. Deleted numbers
  are retained and never reassigned. Numbering does not reset yearly.
- Bill Number filter works alongside category, customer and date filters. Numbers appear
  in ledger/history rows, receipts, sharing text, statement/full exports and report spreadsheets.
  Global exports now follow the visible filters and split cash/grams by actual asset type.
- Attachments are customer property photos (for example gold being received), optionally
  added with the transaction. Cloudinary continues to hold authenticated private assets.
- Owner can read full history and delete transactions/manage role passwords. Staff can
  add customers/transactions and read non-deleted transactions created in the last 24 hours.
  View can read that same history but cannot write. Customer contact data/current balances
  remain readable. The 24-hour rule uses server creation time, not backdated transaction date.
  Both RLS and the app enforce the history boundary. Shared role accounts still share an
  audit identity; individual staff attribution would require separate accounts.
- Offline status is visible; open forms are kept while the tab remains open. Restoring
  connectivity, returning to the tab, Realtime resubscription or manual refresh reloads data.
  Requests time out after 45 seconds. Failed refreshes retain last loaded data with an error.
  Repeated same-user sign-in/token events do not reset the form. Changed roles are rechecked
  at refresh and force a fresh sign-in. No automatic offline write queue or reload-persistent
  draft is implemented; reconnect and retry an unconfirmed save without changing its details.
- The obsolete cloud path was removed from the local-only provider. Contexts/hooks were split
  out of component files and inherited lint issues corrected. Local demo storage remains
  separate; demo numbers are device-local, not production counters.
